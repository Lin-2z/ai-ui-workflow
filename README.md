# AI UI Workflow · V3

面向个人 AI UI 设计与开发协作的轻量指令仓库。

**核心原则：先明确产品目标与最小实现边界，再确定设计交付深度。** 设计应消除实现所需的关键不确定性，而非以产出更多效果图或文档为目标。

## 角色与文件

| 角色 | 文件 | 职责 |
| --- | --- | --- |
| UI / UX Designer | [`prompts/designer.md`](prompts/designer.md) | 视觉探索、Human Taste 收敛、必要交互设计和设计交接 |
| 独立 UI / UX Reviewer | [`prompts/reviewer.md`](prompts/reviewer.md) | 基于结果独立评审，发现重要问题并主动收敛 |
| UI Implementation（Claude Code / Codex） | [`prompts/implementation.md`](prompts/implementation.md) | 复用工程能力、最小改动、真实运行验证 |

## 使用方式

1. 先用已有页面、项目资料或只读源码侦察确认产品目标、不可改变的行为和大致实现路径。
2. 按需复制 `designer.md` 到独立的 ChatGPT Designer 对话，再提供**本次任务**的截图、约束和目标。
3. 需要独立评审时，在**另一个对话**使用 `reviewer.md`，只提供当前设计、目标、必要约束和参考，不提供完整实现历史。Reviewer 仅提出建议，经人确认后才成为修改指令。
4. 设计完成后，提供对应素材与必要交接说明；在 Claude Code / Codex 使用 `implementation.md` 作为 **UI 专项补充**，不覆盖全局 `AGENTS.md` / `CLAUDE.md` 或团队项目规则。
5. 最终以实际运行的页面、图片或安装器为验收依据；若真实实现与概念图冲突，按已确认的产品与工程边界处理。

## 按需选择交付深度

- **资源替换**：例如安装器头图、侧边图、品牌 Banner。优先交付可实际使用的素材、尺寸格式、使用位置与简短验收说明。框架原生行为不需要重画交互。
- **已有页面美化**：保留既有功能与交互，交付受影响页面或组件的设计图与必要状态。
- **新增交互/功能**：补齐入口、流程、抽屉/Dialog、关键状态图及数据反馈，不把关键产品决策留给 Coding Agent 猜测。

分类是判断工作量的工具，不是强制流程。简单任务可以跳过完整探索与独立评审；重大视觉方向未定时，先做 2～3 个有实质差异的候选，并由用户进行 Human Taste 选择。

## 版本维护

本仓库使用 Git 历史记录迭代，不强制维护额外的计划、评审或版本文档。

- 任何指令调整都直接修改对应的 `prompts/*.md`，保持独立文件可复制使用。
- 提交使用简洁的 Conventional Commits，例如 `docs(designer): clarify asset handoff`。
- 审阅改动后再 `git push`，不要将自动提交等同于自动推送。
- 大幅行为变化可以在提交信息中说明原因；发布稳定版本时可用 Git Tag（如 `v3.0.0`），**无需一开始就引入复杂发布流程**。
- 不向仓库存放公司源码、内部截图、密钥、客户信息或其他非公开业务资料。建议仓库保持 **Private**。
